# P4 · 质量、可靠性与发布

## 目标、前置与文件所有权

将 Beta 收敛为可发布 RC。前置条件是 P0–P3 全部完成，尤其是 P0 的 CH340/CP210x 实机门禁。此阶段拥有性能/发布脚本、测试报告、可访问性补强和最小必要的性能修复；不得引入新产品功能。

本阶段创建 `Scripts/{pty_stress.py,build_release.sh,notarize.sh,verify_release.sh,ExportOptions.plist}`、`Docs/{PerformanceReport,RealDeviceTestMatrix,ReleaseChecklist,Licenses}.md` 及性能/可访问性测试；仅按测试结论修改控制台、退出、错误呈现和签名配置。

## 冻结发布接口

`build_release.sh` 只负责 archive/export，`notarize.sh` 只负责提交、等待与 staple，`verify_release.sh <app-path>` 必须验证签名、entitlement、Gatekeeper、公证和包内无用户数据。三者都不得保存证书、密码或 notarization 凭据；凭据只经本机钥匙串 profile 提供。

## 实现顺序

1. 以 Instruments 与 PTY 压测验证 115200 bps 连续 30 分钟；控制台 UI 维持 16–50 ms 批处理、缓存上限和内存平台。只有 SwiftUI 渲染无法达标时，才引入受测的 `NSTextView` bridge。
2. 完成退出确认、错误三段式文案与可复制技术详情；验证写超时、拔出、日志失败、损坏持久化和未保存编辑的恢复路径。
3. 完成 VoiceOver、键盘操作、对比度、Reduce Motion、深浅色和 macOS 14 Material 降级走查。
4. 在 Release 签名 App 上执行 CH340、CP210x、FTDI、CDC-ACM 矩阵；更新依赖许可证清单。
5. 使用 Developer ID、Hardened Runtime、Sandbox entitlement 归档、导出、公证、staple 和 Gatekeeper 验证；验证干净机器首启和应用包不含用户数据。

## 验证与完成条件

- 性能报告记录输入速率、记录数、截断、内存、CPU、无响应情况和 Instruments 证据；30 分钟测试无崩溃、无队列失控。
- `Docs/RealDeviceTestMatrix.md` 的必测项无失败；缺少硬件必须阻止 RC，不以“未测”替代通过。
- Release 测试、签名验证、notarization、stapler、`spctl` 和干净账户首启全部通过。
- 运行 `xcodebuild test -scheme SerialMonitor -configuration Release`、`python3 Scripts/pty_stress.py --baud 115200 --duration-min 30` 与 `Scripts/verify_release.sh`；三者均通过。
- `Docs/ReleaseChecklist.md` 为 AC-01 至 AC-10 保存证据路径；全部勾选后才生成 RC。
