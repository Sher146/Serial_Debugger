## 2. 目标与完成定义（Definition of Done）

- [ ] 每条 RX/TX 记录以一行 UTF-8 JSONL 落盘，字段与需求文档 §6.1 完全一致（`timestamp`/`direction`/`format`/`data`/`bytesBase64`/`source`，预设来源另含 `presetID`/`presetName` 快照）。
- [ ] 文件名符合 `SerialMonitor_yyyyMMdd_HHmmss_<port>.log`，端口名经 02 的安全清洗函数处理。
- [ ] 创建时机正确：用户手动开始记录；或设置开启自动记录且连接成功时自动创建。
- [ ] 写入为串行异步：日志 I/O 不在 MainActor；UI 与收发管线不等待磁盘 I/O；缓冲与 flush 策略明确且可测。
- [ ] 写入失败立即停止日志，提示文件路径与错误原因，串口会话不受任何影响（需求 §13）。
- [ ] 轮转到达阈值时新建文件并追加 `_001`/`_002` 序号，旧文件不自动删除。
- [ ] 停止记录 / 关闭会话 / 应用退出前均有确定性的 flush + close；崩溃恢复标记在 Application Support 中正确写入与清理。
- [ ] 异常退出后下一次启动提示"存在未正常结束的日志"并给出路径，提示后清理标记。
- [ ] 状态栏日志状态点（记录中红色呼吸点 / 未记录灰色）符合设计规范三重表达（图标 + 文字 + 颜色），点击打开日志详情 Popover。
- [ ] 日志详情 Popover 展示：当前文件路径、大小、开始时间、轮转阈值、停止记录、在访达中显示。
- [ ] 日志目录可通过 NSOpenPanel 更换，默认 `~/Documents/Serial Monitor Logs/`。
- [ ] 第 9 节测试清单全部通过；`swift build` 在严格并发模式下无警告。

## 3. 范围

### In scope

- JSONL 日志编码（`CommunicationRecord` → 单行 JSON）、日志文件创建 / 追加 / flush / close。
- 文件命名、端口名清洗调用、轮转命名与阈值判定。
- 写入缓冲与周期性 flush；写入失败的停止与上报。
- 崩溃恢复标记的写入、正常清理、启动检测与提示数据。
- 与 `SessionCoordinator` 的挂接（自动开始、异常结束、退出 flush）。
- 日志状态 UI：状态栏日志点、日志详情 Popover、目录选择面板、菜单命令接口定义。
- 日志默认目录、轮转阈值、自动记录开关的数据模型与默认值（设置窗口 UI 在 07）。

### Out of scope

- 导出可读文本日志（需求 §18：后续版本，JSONL 是唯一落盘格式）。
- 日志文件的查看器 / 搜索 / 过滤 UI。
- 日志压缩、自动清理、云同步、上传（需求 §14 明确禁止上传同步）。
- 设置窗口本体与菜单本体（07）；快捷键绑定（07）。
- 多会话并行日志（V1.0 单会话，按 `sessionId` 建模预留但不实现多文件并行）。

### 明确禁止事项

- 禁止在 MainActor 上执行任何文件写入、flush 或目录创建。
- 禁止引入第三方依赖（日志仅用 Foundation：`FileHandle`/`JSONEncoder`/`FileManager`）。
- 禁止修改 JSONL 字段名、字段顺序语义或新增未定义字段——落盘格式是契约。
- 禁止在写入失败时停止或重启串口会话。
- 禁止自动删除任何历史日志文件（包括轮转旧文件与崩溃残留文件）。
- 禁止为"易读性"改变落盘内容；UI 易读投影只能在展示层从 JSONL 字段另行生成。

    func flushAndClose() async

### 6.2 JSONL 落盘格式（契约，字段名与语义不得变更）

每行一个 JSON 对象，UTF-8 编码，行尾 `\n`：

| 字段 | 类型 | 定义 |
|---|---|---|
| `timestamp` | string | ISO8601，带 3 位毫秒与时区偏移，如 `2026-08-15T18:04:12.235-05:00`；使用记录发生时的本地时区 |
| `direction` | string | `"RX"` 或 `"TX"` |
| `format` | string | 记录生成时的显示格式：`"ascii"` 或 `"hex"` |
| `data` | string | 易读投影：hex 为 `"55 AA 01 00"`（大写、单空格分隔），ascii 为按设置编码解码的字符串（含可见 `\r\n` 转义） |
| `bytesBase64` | string | 原始字节 Base64，是数据可信的唯一权威；`data` 仅为人读 |
| `source` | string | `"serial"`（RX）/ `"manual"` / `"autoSend"` / `"preset"` |
| `presetID` | string | 可选；`source == "preset"` 时存在，UUID 字符串快照 |
| `presetName` | string | 可选；`source == "preset"` 时存在，发送时刻的预设名快照 |

需求文档 §6.1 两行示例（必须能通过本文档编码器逐字节复现其结构）：

```jsonl
{"timestamp":"2026-08-15T18:04:12.235-05:00","direction":"RX","format":"hex","data":"55 AA 01 00","bytesBase64":"VaoBAA==","source":"serial"}
{"timestamp":"2026-08-15T18:04:13.010-05:00","direction":"TX","format":"ascii","data":"AT+RST\r\n","bytesBase64":"QVQrUlNUDQo=","source":"manual"}
```

逐字段解释（以第 1 行为例）：设备在本地时区 -05:00 的 18:04:12.235 送达一块 4 字节数据（RX）；用户当前以 HEX 查看，故 `format` 为 `hex`、`data` 为 `"55 AA 01 00"`；`bytesBase64` 是 `55 AA 01 00` 四字节原文的 Base64（`VaoBAA==`），事后无论切换何种显示格式都能从它还原真相；`source` 为 `serial` 表示来自设备而非发送队列。第 2 行是用户手动发送（`manual`）的 ASCII 指令 `AT+RST\r\n`，`bytesBase64` 为 `QVQrUlNUDQo=`（含 CRLF 共 7 字节）。

**投影分离原则**：落盘的 `data` 字段固定按上述规则生成，与 UI 当前显示格式无关；UI 易读文本由控制台投影另行生成，二者互不影响。切换 ASCII/HEX 不重写已落盘内容（需求 §5.2）。

/// 日志服务状态（需求 §13 + 设计规范 §5.1 三重表达的数据源）。
public enum LogServiceState: Sendable, Equatable {
    case idle                          // 未记录
    case recording(LogSessionInfo)     // 记录中
    case failed(LogFailure)            // 因写入失败已停止（会话不受影响）
}

public struct LogSessionInfo: Sendable, Equatable {
    public let fileURL: URL            // 当前正在写入的文件
    public let startedAt: Date         // 本次记录开始时间
    public let portPath: String        // 来源端口原始路径
    public var rotationIndex: Int      // 0 = 首个文件，1 起为 _001/_002…
    public var currentFileSize: UInt64 // 当前文件已写入字节数（含缓冲）
}

public struct LogFailure: Sendable, Equatable {
    public let fileURL: URL            // 出错的文件路径（Alert 必须展示）
    public let errorDescription: String
    public let occurredAt: Date
}

/// 日志设置值对象。持久化（UserDefaults）与设置窗口 UI 在 07；
/// 本文档只定义模型与默认值，并提供 UserDefaults 读写扩展。
public struct LogSettings: Sendable, Equatable, Codable {
    /// 自定义目录；nil 表示默认 ~/Documents/Serial Monitor Logs/
    public var customDirectoryBookmark: Data? = nil   // security-scoped bookmark
    /// 连接成功后自动开始记录（需求 §5.1 / §6.1 创建时机）。
    public var autoLogOnConnect: Bool = false
    /// 轮转阈值（字节）。默认 10 MiB；合法范围 1 MiB…1 GiB，越界值回退默认。
    public var rotationThresholdBytes: UInt64 = 10 * 1024 * 1024

    public static let `default` = LogSettings()
    public static let minRotation: UInt64 = 1 * 1024 * 1024
    public static let maxRotation: UInt64 = 1024 * 1024 * 1024

    public var sanitized: LogSettings {
        var copy = self
        if copy.rotationThresholdBytes < Self.minRotation
            || copy.rotationThresholdBytes > Self.maxRotation {
            copy.rotationThresholdBytes = Self.default.rotationThresholdBytes
        }
        return copy
    }
}

public enum LogError: Error, Sendable, Equatable {
    case directoryUnavailable(String)      // 目录解析/创建失败
    case fileCreationFailed(String)        // 文件创建失败
    case writeFailed(String)               // 写入/flush 失败（触发停止）
    case alreadyRecording
    case notConnected                      // 未连接时请求开始（菜单可用条件兜底）
}

**`LogService` 内部行为规约（实现必须遵守）：**

1. `startLogging`：`resolveDirectory` → `baseFileName` → 构造 writer → 写 `CrashMarker` → 状态置 `recording`（rotationIndex = 0）。任何一步抛错即清理半成品（关闭句柄、删标记）并抛出。
2. `log`：仅当状态为 `recording` 时生效；编码后经 writer 写入缓冲并累加 `currentFileSize`；每次写入后检查 `currentFileSize >= rotationThresholdBytes`，达成则执行轮转：flush + close 当前 writer → 打开 `rotatedFileName` 新 writer → `rotationIndex += 1` → 更新状态中的 `fileURL`。
3. 周期 flush：开始记录时启动内部 `Task`，每 500 ms 调 `writer.flush()`；停止/轮转/退出时取消。崩溃最坏丢失 500 ms + 64 KiB 内数据，属可接受窗口。
4. 任何 `writeLine` / `flush` / 轮转建文件抛错：置状态 `failed(LogFailure)`（携带当前 fileURL 与错误描述）→ best-effort close → `CrashRecoveryMarker.clear()`（受控停止，不留给启动提示）→ 取消周期任务。**不触碰串口会话**（需求 §13）。
5. `stopLogging` / `flushAndClose`：`writer.close()`（含 fsync）→ `CrashRecoveryMarker.clear()` → 取消周期任务 → 状态置 `idle`。
6. 状态变化通过 `AsyncStream` 连续发出（含文件大小增长），供 ViewModel 投影。
