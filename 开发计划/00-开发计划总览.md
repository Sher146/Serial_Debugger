## 1. 文档定位与使用方式

本目录是 Serial Monitor V1.0 的完整开发计划，拆分为 9 份文档。每份文档**自包含**：包含目标、范围、文件清单、接口定义、实现步骤、验收标准与防漫游约束。

**给 AI coding agent 的使用规则：**

1. 一次只执行一份文档，按编号顺序推进；前置文档未完成不得开始后续文档。
2. 开始编码前，先完整阅读当前文档，再阅读其"依赖与前置条件"列出的上游资料章节。
3. 只做当前文档"涉及文件清单"中列出的文件；发现需要改动清单外文件时，停下来记录问题，不得自行扩大范围。
4. 文档中的 Swift 接口定义是契约，照抄实现；签名变更必须回写本文档。
5. 每完成一个实现步骤，执行该步骤的"自验证方式"，通过后再继续下一步。
6. 需求文档、设计规范、Figma 原型三者冲突时，优先级为：**需求文档 > 设计规范 > Figma 原型**；冲突点记录到本文档第 9 节"风险与决策点"，不得自行取舍。

## 2. 产品与技术基线

| 项 | 基线 |
|---|---|
| 产品形态 | macOS 本地桌面应用，单窗口、单活跃串口会话 |
| 系统基线 | macOS 14+；macOS 26 启用 Liquid Glass 增强视觉，低版本优雅降级 Material |
| UI 框架 | SwiftUI 为主；AppKit 仅用于 NSOpenPanel/NSAlert/NSTextView 桥接/菜单窗口细节 |
| 语言与构建 | Swift 6（全工程严格并发检查）、Xcode、Swift Package Manager |
| 并发模型 | Swift Concurrency：actor、async/await、AsyncStream；UI 状态一律回 MainActor |
| 串口访问 | 独立 SerialCore 抽象层（`SerialPorting` 协议）；第三方库仅允许 Infrastructure 层引用 |
| 持久化 | Codable JSON（带 schemaVersion）+ UserDefaults + FileManager；**不引入数据库** |
| 日志格式 | UTF-8 JSONL 落盘，UI 层另做易读投影 |
| 数据规则 | RX/TX 一律保存原始字节（Data）；ASCII/HEX 仅是展示/输入编码，切换不改原始数据 |
| 调度规则 | 普通自动发送与预设循环互斥；单一会话协调器串行裁决发送、记录、状态机 |
| 本地化 | 首发简体中文；所有用户可见字符串走 String Catalog |

V1.0 明确不做：网络/蓝牙通信、多串口同时连接、协议解析器/图表/脚本、数据库/云同步、Windows/Linux 应用、自动更新。

## 3. 全局架构约定

### 3.1 分层（MVVM + 单向数据流）

| 层 | 职责 | 禁止事项 |
|---|---|---|
| Presentation | SwiftUI View、Commands、AppKit bridge、可访问性 | 不得直接打开串口、写文件、解析 HEX |
| ViewModel | 状态投影、用户意图校验、提示信息 | 不得持有 file descriptor 等底层资源 |
| Application | SessionCoordinator、SendScheduler、LogService、PresetService | 不得依赖 SwiftUI / AppKit |
| Domain | 记录模型、配置、状态机、编码规则、错误模型 | 不得依赖第三方串口库、SwiftUI、AppKit |
| Infrastructure | SerialPortAdapter、端口发现、文件、UserDefaults | 不得修改 UI 状态 |

### 3.2 工程目录结构（目标终态，各文档按需创建）

```
SerialMonitor/
  App/                 SerialMonitorApp、Commands、AppDelegate bridge
  Features/Session/    SessionView、SessionViewModel、ConsoleView 等主工作区视图
  Features/Settings/   SettingsView、SettingsViewModel
  Features/Presets/    PresetInspector、PresetEditSheet
  Domain/              Models、Validation、Encoding、StateMachine、Protocols
  Application/         SessionCoordinator、SendScheduler、LogService、PresetService
  Infrastructure/      SerialCore/（SerialPorting + 适配器）、Persistence/、FileSystem/
  Shared/              Formatting、DesignTokens、Localization、AccessibilityHelpers
  Tests/               Unit、Integration（伪终端/Mock）、UITests
```

### 3.3 并发与数据管线铁律

- 数据管线：`RX: Device → SerialPortAdapter → RX actor → RecordStore → [Console 投影, LogWriter]`；`TX: Input/Preset → Validator+Encoder → TX 队列 actor → SerialPortAdapter → RecordStore + LogWriter`。
- `SessionCoordinator` 是唯一拥有连接、自动发送任务、预设循环任务的 actor；启动新任务前必须取消并 await 旧任务结束。
- TX 按 FIFO 串行化；手动、自动、预设发送进入同一队列，禁止跨来源并发写串口。
- RX 读、TX 写、日志写分别在非 MainActor 执行；UI 可观察状态回 MainActor 更新。
- RecordStore 保存原始 Data，展示字符串按当前偏好惰性生成；切换 ASCII/HEX 只重建展示投影。
- 默认缓存上限：50,000 条记录 或 16 MiB 原始字节，任一先到则淘汰最早项（可配置）。
- 高流量下 UI 刷新可批处理到 16–50 ms；115200 bps 持续输入时界面不得失响应。

## 5. 全局工程规范

- 所有用户可见字符串使用 String Catalog，首发 zh-CN，预留 en。
- 控制台默认 SF Mono / Menlo 12pt；UI 用系统字体；字号 10–18pt 可调（设置项）。
- 设计令牌以 Figma 原型 `设计图/src/index.css` 的 CSS 变量为暗色基准，落地为 Asset Catalog 语义色（支持深浅色）；RX=#2997ff 蓝、TX=#30d158 绿、警告=#ff9f0a 橙、错误=#ff453a 红，弱底色为对应色 12% 不透明度。
- 窗口最小尺寸 980 × 680 pt。
- 时间戳显示格式 `HH:MM:SS.mmm`（24 小时制 + 3 位毫秒）；日志落盘用 ISO8601 带毫秒与时区。
- 状态表达必须三重：图标 + 文字 + 颜色，不允许只用颜色。
- 第三方依赖通过 SPM 锁定版本；任何新依赖必须先登记（版本、许可证、用途）再引入。
- 测试分层：纯 Swift 单元测试（编码/状态机/截断/校验）→ 状态机事件序列测试（虚拟时钟）→ 伪终端/Mock SerialPorting 集成测试 → XCUITest。

## 6. 全局防漫游规则（每份子文档末尾重申）

1. 不创建当前文档文件清单之外的文件；不修改清单之外的已有文件。
2. 不引入当前文档未列出的第三方依赖。
3. 不实现标注为"后续版本/Out of scope"的功能（多会话、协议解析、图表、脚本、导出可读文本等）。
4. 不做顺手重构、重命名、格式化无关代码。
5. 接口契约以文档中的 Swift 定义为准；确有实现障碍时先记录再请示，不静默改签名。
6. Figma 原型中的已知瑕疵不得照抄（见 04 文档"原型瑕疵修正清单"）。
7. 每个实现步骤完成后必须运行其自验证命令/测试，红了就先修，不跳过。
8. 需求矛盾或信息缺失时，在文档"风险与决策点"追加记录并停止该分支工作，不自行发明需求。
