# P0 · 工程初始化与串口验证

## 目标、前置与文件所有权

建立可测试的 macOS 工程和可替换的串口边界，并以真实证据决定使用候选库或 POSIX/termios。前置条件：包含 macOS 26 SDK 的完整 Xcode、Swift 6 工具链、Apple 签名能力、PTY，以及 CH340/CP210x 回环设备；FTDI/CDC-ACM 作为兼容矩阵补充。

本阶段唯一创建：`SerialMonitor.xcodeproj`、`SerialMonitor/App/SerialMonitorApp.swift`、`SerialMonitor/SerialMonitor.entitlements`、`Packages/SerialCore/**`、`SerialMonitor/Infrastructure/Serial/**`、`SerialMonitor/Tests/Serial/**`、`Scripts/verify-development-environment.sh`、`Docs/DevelopmentEnvironment.md`、`Docs/SerialCompatibilityMatrix.md`、`Docs/Dependencies.md`。不创建业务 UI、日志、预设或会话协调器。

## 冻结接口

`SerialCore` 只依赖 Foundation/Darwin，并定义以下公开值类型：`SerialPortDescriptor`、`SerialConfiguration`（path、baudRate、dataBits、parity、stopBits、flowControl）、`SerialError`、`SerialConnectionEvent`。

`SerialPorting` 固定为异步能力：枚举端口、`open(configuration:)`、幂等 `close()`、`write(_:deadline:)`、`incomingBytes()` 和 `connectionEvents()`。`deadline` 必须使写入在有界时间内成功、失败或取消；设备移除必须先发 `.deviceRemoved`，再结束 RX stream。上层不得接触候选库的类型或错误。

## 实现顺序

1. 创建 macOS 14+ App、Unit/UI Test target、本地 SerialCore 包与严格并发设置；添加 `.gitignore` 规则，禁止提交 `.build`、DerivedData 和签名产物。
2. 先实现 SerialCore 值类型、错误分类和协议；编写 Codable、默认值、errno 映射、stream 结束顺序测试。
3. 用 PTY 实现测试替身，并分别验证打开、参数设置、双向读写、占用、拔出、重复 close、连接中取消及阻塞写超时。
4. 为候选库实现仅限 Infrastructure 的适配器；若任一写超时、取消、热拔出或串行权限无法满足，即停止该分支并实现 POSIX/termios + IOKit 适配器，不改变 SerialCore。
5. 在 App Sandbox（`com.apple.security.device.serial`）与开发签名下验证发现、打开、读写和无 entitlement 的权限错误；完成 CH340/CP210x 的 9600 与 115200 回环、拔出、占用测试，并记录 FTDI/CDC-ACM 结果。

## 验证与完成条件

- `xcodebuild build -scheme SerialMonitor` 与 `xcodebuild test -scheme SerialMonitor -only-testing:SerialMonitorTests/SerialCoreTests` 全绿、零严格并发警告。
- PTY 覆盖写入超时/取消；取消或关闭不得无限等待。
- `Docs/SerialCompatibilityMatrix.md` 无空单元格，CH340/CP210x 的必测项均通过；`Docs/Dependencies.md` 记录版本、哈希、许可证和升级策略。
- P0 结论只能写为“采用 <实现>”或“采用 POSIX/termios”；实机缺项时状态为“未决”，不得进入 P4。
