# Serial Monitor V1.0 开发总览

> 状态：重置后的开发基线｜权威输入：`设计与需求文档.html`、`Serial_Monitor_UI设计规范_V1.0.html`、`设计图/`

## 目标与边界

交付 macOS 14+ 的单窗口、单活跃串口会话调试工具：发现并连接串口，可靠收发原始字节，支持 ASCII/HEX 投影、自动发送、预设、JSONL 日志、本地设置和原生菜单。首发 zh-CN。视觉优先级明确为 **macOS 26 的原生 Liquid Glass 体验优先**；macOS 14–25 必须以系统 Material 保持同等信息层级和可读性。

明确不做：多会话、网络/蓝牙、协议解析、图表、脚本、云同步、数据库、自动更新和跨平台客户端。

需求文档优先于 UI 规范，UI 规范优先于 `设计图/` 原型。冲突必须登记在本文件的风险表后再继续。

## 架构与接口纪律

目录终态为 `SerialMonitor/{App,Features,Domain,Application,Infrastructure,Shared,Tests}`，另有零第三方依赖的 `Packages/SerialCore`。Swift 6 严格并发；UI 状态只在 `@MainActor` 更新；串口、日志与调度均不运行在 MainActor。

| 层 | 允许职责 | 禁止事项 |
|---|---|---|
| Presentation | SwiftUI、Commands、AppKit bridge、ViewModel | 串口 I/O、文件 I/O、HEX 解析 |
| Application | `SessionCoordinator`、`SendScheduler`、`LogService` | 依赖 SwiftUI/AppKit |
| Domain | 模型、校验、状态机、缓存、格式化 | 第三方串口库 |
| Infrastructure | 串口适配、文件与 UserDefaults | 修改 UI 状态 |

唯一边界如下，后续文档只能消费前序阶段已经交付的签名，禁止写“假定签名”。

- `SerialPorting` 是唯一串口抽象；任何候选库或 POSIX 代码只能位于 Infrastructure。
- `SessionCoordinator` 是唯一持有 `SerialPorting`、TX 队列、调度器和日志服务的 actor，并实现 UI 使用的 `SessionClient`。
- `SessionClient.subscribe()` 为每个订阅者创建独立 `AsyncStream<SessionEvent>`；不得共享单消费者 stream。
- `SessionEvent` 固定包含端口列表、会话状态、批量记录、字节/截断统计、日志状态、最近错误六类投影。
- `CommunicationRecord.rawBytes: Data` 是 RX/TX 的唯一事实来源；ASCII/HEX、控制台与日志字段均是投影。

## 阶段与门禁

| 阶段 | 文档 | 交付物 | 开始条件 | 结束门禁 |
|---|---|---|---|---|
| P0 | 01 | 工程骨架、SerialCore、适配器决策 | 完整 Xcode | PTY、沙盒、CH340/CP210x 实机均通过；否则采用 POSIX/termios |
| P1 | 02 | 可收发的开发版与统一 Application 边界 | P0 接口冻结 | 状态机、FIFO、取消、拔出、写超时测试通过 |
| P2 | 03 | 主工作区 UI | P1 `SessionClient` 可 mock | macOS 26 Glass 视觉走查、Material 降级、Preview、单元/UI 冒烟和 980×680 布局通过 |
| P3 | 04 | 功能完整 Beta | P2 完成 | 调度、预设、日志、设置与菜单测试通过 |
| P4 | 05 | RC 与发布包 | P0–P3 完成 | 压测、可访问性、实机矩阵、签名/公证通过 |

P0 的纯契约和 PTY 子项完成后，可并行推进不依赖真实硬件的 P1/P2；但在 CH340/CP210x 实机门禁通过前，不得将任何串口实现标为“已采用”，也不得进入发布阶段。

## 本文档所有权与验证

本文档唯一拥有本目录的阶段顺序、跨阶段架构规则、验收映射和风险编号；接口定义由 01/02 所有，发布脚本由 05 所有。本文件不得复制其实现签名。

每次阶段门禁检查均运行 `xcodebuild test -scheme SerialMonitor`；P0 另运行其 SerialCore/PTY 测试，P4 另运行 `Scripts/verify_release.sh`。总览完成条件是所有阶段文档均有明确文件所有权、冻结接口、实现顺序、命令和完成条件，且不存在“假定签名”表述。

## 全局验收与风险

- AC-01/02：端口发现、连接/关闭、异常和非法状态转移。
- AC-03/04：原始字节接收、ASCII/HEX、暂停显示、FIFO 发送与输入校验。
- AC-05/06：自动发送互斥、预设 CRUD/排序/循环与恢复。
- AC-07/08：JSONL、轮转、失败隔离、设置持久化和即时生效。
- AC-09/10：菜单/快捷键、深浅色、VoiceOver、115200 bps 持续 30 分钟。

| 编号 | 风险 | 当前决策 |
|---|---|---|
| R1 | 串口库兼容性与写取消 | P0 不预选库；达不到有界取消/超时即使用 POSIX/termios |
| R2 | 实机硬件缺失 | CH340 与 CP210x 是 P0/P4 必测门禁；缺失时只能推进非发布工作 |
| R3 | 长控制台性能 | P2 先以 SwiftUI 批处理实现；P4 以数据决定是否引入 `NSTextView` bridge |
| R4 | 严格并发 | 每阶段以 Xcode Swift 6 complete 检查和测试为完成条件 |
| R5 | Glass API 与低版本回退差异 | 仅由 P2 的 `VisualEffectsSupport` 封装系统 API；P4 在 macOS 26 与 macOS 14 各归档同场景截图 |
