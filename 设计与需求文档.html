1. 产品目标与成功标准

Serial Monitor 是面向 MCU、传感器、USB-UART、RS-232/RS-485 转换器和 AT 指令设备的本地串口调试工具。它必须让使用者在不理解底层实现的前提下，快速选择串口、可靠收发字节流、复用常用命令并保存可追溯日志。

目标

可观测成功标准

快速开始

从启动到成功打开一个已识别串口，典型操作不超过 3 步。

数据可信

每条 RX/TX 记录都可追溯到原始字节、时间、方向、显示格式和发送来源。

高频可用

持续接收时 UI 不阻塞；缓存达到上限时有确定的截断策略。

macOS 原生体验

菜单、快捷键、窗口行为、深浅色和材质与系统习惯一致。

可维护

串口库、日志格式、持久化和 UI 解耦，可替换或扩展而不重写业务逻辑。

2. 产品范围、非范围与版本边界

2.1 V1.0 范围

  • 单一活跃串口会话：发现、参数配置、打开/关闭、连接状态与错误。
  • 字节流收发：ASCII / HEX，时间戳，暂停显示，清空与自动滚动。
  • 单条自动发送、可排序预设、预设循环发送、日志记录和本地设置。
  • macOS 菜单、快捷键、帮助入口、关于窗口、异常退出防护。

2.2 明确不在 V1.0 范围

  • 网络、蓝牙、TCP/UDP、MQTT 或 WebSocket 通信。
  • 数据库、云同步、多用户协作、账号体系。
  • 协议解析器、图表、脚本语言、插件市场、自动化测试脚本录制。
  • 多串口同时连接；此能力应在后续通过 SessionManager 扩展。
  • Windows / Linux 可执行应用。

5. 功能需求

5.1 串口发现、配置与连接

  • 应用启动时按照设置自动刷新端口列表；用户可通过刷新按钮或菜单命令手动刷新。
  • 仅展示可打开的调用端口（macOS 优先展示 /dev/cu.*）；每项显示路径、可读名称和可用的 USB 厂商/产品信息。
  • 配置字段包括 Port、Baud Rate、Data Bits、Parity、Stop Bits、Flow Control。默认值可由设置恢复。
  • 连接状态为 disconnected、opening、connected、closing、error；任何时刻只能处于一个状态。
  • 打开失败、设备拔出、配置不支持、读写失败必须产生结构化错误：分类、系统错误码、用户可读说明、发生时间、是否可重试。
  • 连接过程中锁定影响打开过程的参数；关闭完成后才允许切换端口。

5.2 接收记录

  • 从串口读取到的每个数据块立即生成一条 RX 原始记录；可以在显示层按连续到达数据块进行合并，但不得改变原始字节。
  • ASCII 显示使用设置指定的文本编码。无法解码字节必须以可识别占位形式显示，不得静默丢弃。
  • HEX 显示使用设置的字节分隔符、大小写和换行规则；例如 “55 AA 01”。
  • 暂停显示只冻结控制台的渲染和自动滚动，后台仍接收、入缓存和写日志；恢复后按时间顺序补显示。
  • 清空操作仅清除内存显示记录，不自动清空正在写入的日志文件；操作前无需关闭端口。
  • 记录数量或字节数达到设置阈值后，从最早记录开始安全淘汰；界面显示累计截断次数与最后一次截断时间。

5.3 数据发送与校验

项目

行为

ASCII 模式

按设置编码转换为 Data；可选追加无 / LF / CR / CRLF。

HEX 模式

允许空白、换行和配置的分隔符；去除空白后必须为偶数个十六进制字符。非法字符、奇数字符数或空数据均不得发送。

触发方式

点击发送按钮或 Cmd+Return；普通 Return 在多行编辑器中换行。

前置条件

连接状态必须为 connected；否则保留输入内容并提示未连接。

记录

成功排入发送队列即创建 TX 记录，包含字节、编码、来源、预设 ID（如有）和发送结果。

失败

底层写入失败时把 TX 记录标记为 failed，显示原因；不可恢复错误转入 error 并停止所有自动发送。

5.4 自动发送与预设循环

  • 普通自动发送重复使用当前发送编辑器内容、当前模式和当前行结束符；间隔单位为毫秒，范围建议 10–3,600,000 ms。
  • 预设至少包含 id、名称、内容、编码模式、启用状态、排序序号、创建时间、更新时间和可选备注。
  • 预设循环只遍历已启用项目，严格按 sortOrder 执行；每次实际发送均生成带 presetID 和 presetName 快照的 TX 记录。
  • 普通自动发送与预设循环不得同时运行。启动其中之一前自动停止另一项，并在状态栏明确显示当前运行模式。
  • 关闭端口、设备拔出、不可恢复读写错误、用户点击停止或应用退出流程都会立即取消计时器与待发送队列。
  • 防止重入：下一次循环必须在上一次发送操作完成或明确失败后才开始；不得因 UI 卡顿而并发堆积定时任务。

6. 日志与持久化需求

6.1 日志文件

日志采用 UTF-8 文本文件，推荐扩展名 .log；为便于机器处理，每一条记录使用一行 JSON Lines（JSONL）格式。用户界面可显示为易读文本，但落盘以固定字段保障可追溯性。

{"timestamp":"2026-08-15T18:04:12.235-05:00","direction":"RX","format":"hex","data":"55 AA 01 00","bytesBase64":"VaoBAA==","source":"serial"}
{"timestamp":"2026-08-15T18:04:13.010-05:00","direction":"TX","format":"ascii","data":"AT+RST\r\n","bytesBase64":"QVQrUlNUDQo=","source":"manual"}

要求

规则

创建时机

用户开始记录或设置为自动记录且连接成功时创建。

文件名

默认 SerialMonitor_yyyyMMdd_HHmmss_<port>.log；端口名需安全清洗。

写入策略

串行异步写入；UI 不等待磁盘 I/O。写入失败必须停止日志并提示文件路径与错误。

轮转

达到阈值时按设置新建下一文件，名称追加 _001、_002；不自动删除旧文件。

结束行为

停止记录、关闭会话或退出前 flush 并关闭；异常退出允许下一次启动提示存在未正常结束日志。

8. 视觉与交互设计规范

界面必须优先使用系统原生控件和布局语义，而不是仿制网页后台。目标是类似 Apple Console、Xcode 或系统设置的干净、轻量、可读的开发工具风格。

维度

设计要求

材质与层次

在支持的系统上使用系统 Material / Liquid Glass API；业务信息区保持足够不透明，避免长日志文字受背景干扰。

颜色

依赖系统 accent color、semantic colors 与深浅色；RX、TX、错误只使用可访问性足够的语义色，并辅以文本标签。

字体

控制台默认 SF Mono / Menlo 等宽字体；UI 沿用系统字体。用户可在设置中调节字体与字号。

状态

不用颜色单独表达状态：同时显示图标、文字和可读状态描述。

动效

仅用于状态变更、抽屉展开和自动滚动；遵守 Reduce Motion。

可访问性

每个交互控件有 VoiceOver 标签；键盘可到达；最小可点击区域符合系统建议。

Liquid Glass 使用边界 采用系统提供的 Glass / Material，而不在日志区大面积叠加透明背景。串口监视器的首要任务是读码清晰；“好看”不能牺牲对比度、选择文本或长时间查看的舒适度。

9. 技术架构与项目结构

架构采用 MVVM + 单向数据流。SwiftUI View 只处理呈现与用户意图；ViewModel 调用应用服务；会话协调器串行协调连接、读写、定时任务与日志；SerialCore 是可替换的基础设施适配层。

层

职责

禁止事项

Presentation

SwiftUI View、Commands、AppKit bridge、可访问性。

不得直接打开串口、写文件或解析 HEX。

ViewModel

状态投影、用户意图校验、提示信息。

不得持有底层 file descriptor。

Application

SessionCoordinator、SendScheduler、LogService、PresetService。

不得依赖 SwiftUI / AppKit。

Domain

记录模型、配置、状态机、编码规则、错误模型。

不得依赖第三方串口库。

Infrastructure

SerialPortAdapter、端口发现、文件、UserDefaults。

不得修改 UI 状态。

11. 关键接口与状态机

11.1 核心协议

protocol SerialPorting: Sendable {
  func availablePorts() async -> [SerialPortDescriptor]
  func open(configuration: SerialConfiguration) async throws

12. 数据处理、并发与性能要求

12.1 数据管线

RX: Device → SerialPortAdapter → RX actor → RecordStore → [Console projection, LogWriter]
TX: Input / Preset → Validator + Encoder → TX queue actor → SerialPortAdapter → RecordStore + LogWriter
  • RX 读取、TX 写入、日志写入分别在非 MainActor 执行。所有 UI 可观察状态回到 MainActor 更新。
  • SessionCoordinator 是唯一拥有自动发送任务和预设循环任务的 actor；启动新任务前必须取消并 await 旧任务结束。
  • TX 按 FIFO 串行化。手动发送、自动发送和预设发送进入同一队列，禁止跨来源并发写串口。
  • RecordStore 保存原始 Data；展示字符串按当前用户偏好惰性生成或缓存。切换 ASCII/HEX 只重建展示投影。
  • 默认缓存建议：最多 50,000 条记录或 16 MiB 原始数据，任一条件先达到则淘汰最早项。默认值必须可配置。
  • 在 115200 bps 持续数据输入场景下，主界面滚动和编辑操作不得因数据流失去响应；高流量可将 UI 刷新批处理到 16–50 ms。

12.2 定时发送规则

问题

处理规则

最小间隔

UI 最小允许 10 ms；默认 1000 ms。过小值保存前校验并提示。

发送耗时超过间隔

不堆积；下一次发送在本次完成后，按单调时钟重新计算。

模式切换

切换 ASCII / HEX、行结束符、端口参数时，运行中的普通自动发送先停止。

预设修改

预设循环运行时使用一次循环开始时的快照；下一轮读取最新已保存顺序。

断开 / 错误

立即取消 Task；状态栏显示停止原因。

14. 安全、隐私与本地化

  • 不上传串口数据、预设或日志；所有数据默认仅保存在用户本机。
  • 日志、预设和错误详情可能含敏感命令或设备标识；界面避免自动复制、自动分享或发送到外部服务。
  • 对文件名、端口名和预设名称做路径安全清洗；不得允许通过名称构造越界路径。
  • 首发提供简体中文；所有用户可见字符串使用 String Catalog 管理，为英文和其他语言预留。
  • 使用 Unicode 和 UTF-8；预设名称、日志路径、错误信息必须支持中文。

18. 风险与待确认项

事项

风险 / 影响

建议决策

最低系统版本

Liquid Glass API 与兼容版本之间需平衡。

以 macOS 14 为运行基线；在 macOS 26 启用增强视觉，低版本优雅降级。

串口库

第三方维护活跃度、权限与边缘参数支持存在差异。

P0 做实机兼容验证；保留 SerialPorting 适配器替换能力。

日志格式

用户可读性与机器可解析性可能冲突。

采用 JSONL 原始落盘；未来可加“导出可读文本”而不改变底层日志。

多会话

后续若支持多个串口，记录、任务和日志要会话隔离。

V1.0 按 sessionId 建模，UI 只暴露一个活动会话。

自动发送最小间隔

过低间隔可能与设备缓冲、USB 转串口驱动冲突。

默认 1000 ms，最小 10 ms；说明不保证设备端处理能力。

19. 参考资料与实施说明

  • Apple SwiftUI / AppKit：用于原生 macOS UI、菜单、窗口与系统视觉能力。
  • Apple IOKit：用于硬件设备与串口发现相关能力；实际通信可经串口库或 POSIX 适配层封装。
  • SerialGate：Swift 6、macOS 13+ 的串口通信候选库；仅作为 Infrastructure 依赖候选，必须经过 P0 验证。
  • 所有第三方依赖应记录版本、许可证、哈希与升级策略；发布前完成许可证清单。

20. 实施结论

推荐基线 以 SwiftUI + AppKit 建立原生体验；以 Swift Concurrency actor 管理串口会话与定时发送；以可替换 SerialCore 隔离串口库；以原始字节记录 + JSONL 日志确保可追溯。这一组合适合先做“基础但精致”的 macOS 串口调试助手，也保留未来支持更多平台的技术空间。
